DNS - DNS Resolution, Terms & Workflow

UNDERSTANDING DNS​

The Domain Name System (DNS) is a hierarchical and distributed naming system that maps human-readable domain names to machine-readable IP addresses.

DNS Design Principles:​

  • Hierarchical: Follows a strict tree-like structure.
  • Distributed: Spread across the globe for massive scalability.
  • Cached: Heavily used at multiple levels to improve performance.
  • Delegated: Responsibility is handed off to avoid central bottlenecks.

Beyond name resolution, DNS supports:

  • Load balancing
  • Failover mechanisms
  • Service separation via subdomains

Dissecting the domain name: www.kubernetes.io.​

PartDescription
.Root — The starting point of the DNS hierarchy. resolvers always assume this.
ioTLD (Top-Level Domain) — Represents a category (e.g., .com, .edu, .io).
kubernetesSecond-Level Domain — Registered under the .io TLD.
wwwSubdomain — A prefix to the main domain used for specific services (web, mail, etc.).

Note on "www": In DNS, "www" is just another subdomain with no special intrinsic meaning. Any behavior (like redirection) must be explicitly configured. DNS maps it via CNAME or A records, but HTTP-level redirection occurs at the web server or CDN.

WHAT HAPPENS WHEN WE TYPE A DOMAIN NAME?​

The DNS lookup flow moves from Top to Bottom through four high-level stages:

Step 1: DNS Query Initiation (Client Side)​

  1. The OS checks its local DNS cache.
  2. If not found, the query is forwarded to a Recursive Resolver (usually provided by your ISP or public services like Google 8.8.8.8).

Step 2: Recursive Resolution (Resolver Side)​

If the record isn't in the resolver's cache, it initiates a series of queries:

  1. Query Root Nameserver: Asks "Who handles .io?"
  2. Query TLD Nameserver: Asks "Who handles kubernetes.io?"
  3. Query Authoritative Nameserver: Asks "What is the IP for docs.kubernetes.io?"
  4. Receive final IP address.

Step 3: Response and Caching​

The resolver caches the result based on its TTL (Time to Live) value and returns the IP to the client system.

Step 4: Connection Established​

The browser uses the IP address to establish a TCP connection, performs a TLS handshake, and sends HTTP requests.

DNS Management Commands​

  • View DNS configuration (macOS): scutil --dns
  • Manually inspect resolution: dig docs.kubernetes.io
    • The SERVER field in the output indicates which resolver handled the query.

Strategy Tip: During infrastructure changes, reduce the TTL well in advance so that updates propagate quickly, then restore the original TTL after the move is complete.

DNS ZONE AND ZONE FILE​

A DNS namespace is too large for one authority. It is divided into DNS Zones, each managed by a specific authority.

  • DNS Zone: A record set for a portion of the DNS hierarchy.
  • DNS Zone File: A database containing all records required to resolve names within that zone.

Mandatory Records:​

  1. SOA (Start of Authority): Defines authority, primary server, and refresh timers.
  2. NS (Nameserver): Defines which servers are authoritative for the zone.

Common Record Types:​

RecordDescription
AMaps a domain to an IPv4 address.
AAAAMaps a domain to an IPv6 address.
CNAMECanonical Name — Points one domain name to another (Alias).
MXMail Exchange — Specifies mail servers. Points to hostnames, never IPs.
TXTProvides arbitrary text (often used for SPF, DKIM, or verification).
NSAuthoritative nameservers for the domain.

DNS SERVER CATEGORIES​

  1. Non-Authoritative Nameservers:
    • Run by ISPs or public providers (Google, Cloudflare).
    • They do not store original records; they speed up queries via caching.
  2. Authoritative Nameservers:
    • Provide original, accurate answers for specific zones.
    • They serve zone data directly and do not perform recursive lookups for other domains.

DOMAIN REGISTRY vs. REGISTRAR​

  • Domain Registry: The "Wholesaler." Manages all names under a specific TLD. (e.g., Verisign manages .com).
  • Domain Registrar: The "Retailer." Allows users to buy and renew names. (e.g., GoDaddy, Namecheap).

Crucial Note: Domain registration and DNS hosting are independent. A registrar manages ownership, while a DNS host (like Route53 or Cloudflare) manages the actual zone files and records.

ROOT ZONES​

The root domain is the starting point of the DNS hierarchy.

  • There are 13 logical root nameservers operated by 12 organizations.
  • The zone file is maintained by IANA and distributed by Verisign.
  • Root servers use Anycast routing, meaning there are actually hundreds of physical instances worldwide for high availability.

DEEP DIVE RESOLUTION FLOW (Summary)​

  1. Client requests cwvj.io.
  2. Local Cache check.
  3. ISP/Public Resolver takes the query.
  4. Resolver asks Root: "Who handles .io?"
  5. Root returns Authoritative NS for .io.
  6. Resolver asks .io TLD NS: "Who handles cwvj.io?"
  7. TLD NS returns Authoritative NS for cwvj.io.
  8. Resolver asks Authoritative NS: "What is the IP for cwvj.io?"
  9. Authoritative NS returns the A record.
  10. Resolver caches and returns IP to Client.
  11. Client establishes connection.
