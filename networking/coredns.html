DNS - CoreDNS in Kubernetes

COREDNS​

Kubernetes uses DNS for service discovery and communication between components. CoreDNS is the default DNS provider since Kubernetes v1.13, replacing the legacy kube-dns implementation.

Key Characteristics:​

  • Deployment: Runs in the kube-system namespace with 2+ replicas.
  • Service: kube-dns ClusterIP service (port 53).
  • Ports:
    • 53/UDP, 53/TCP: DNS resolution.
    • 9153/TCP: Prometheus metrics (request counts, latency, cache stats).

Check CoreDNS status:​

kubectl get deployment -n kube-system coredns
kubectl get svc -n kube-system kube-dns
kubectl get pods -n kube-system -l k8s-app=kube-dns

DEMO 1: DNS CONFIGURATION INSIDE A POD​

1. Using netshoot for Testing​

nicolaka/netshoot is a troubleshooting image with tools like nslookup, dig, ping, and curl.

kubectl run debug-pod -it --image=nicolaka/netshoot --rm --restart=Never -- bash
  • --rm: Delete pod on exit.
  • --restart=Never: Run as a one-off pod.

2. Understanding /etc/resolv.conf​

Check configuration inside the pod:

cat /etc/resolv.conf

Typical Output:

search default.svc.cluster.local svc.cluster.local cluster.local
nameserver 10.96.0.10
options ndots:5
  • search: Domains to append for short name resolution.
  • nameserver: CoreDNS service IP.
  • ndots:5: If a name has fewer than 5 dots, K8s tries the search domains first before trying the name as an absolute FQDN.

3. /etc/hosts vs /etc/resolv.conf​

DNS resolution first checks /etc/hosts for static mappings. Example: 10.244.2.3 www.kubernetes.io Note: Tools like nslookup and dig typically bypass /etc/hosts and query the nameserver directly.

DEMO 2: VERIFY DNS RECORDS​

Step 1: Create test resources​

# Default Namespace
kubectl create deployment nginx-deploy --image=nginx --replicas=2
kubectl expose deployment nginx-deploy --name=nginx-svc --port=80

# App1 Namespace
kubectl create namespace app1-ns
kubectl create deployment app1-deploy --image=nginx -n app1-ns
kubectl expose deployment app1-deploy --name=app1-svc --port=80 -n app1-ns

# Headless Service (StatefulSet style)
kubectl create deployment redis-deploy --image=redis --replicas=3
kubectl expose deployment redis-deploy --name=redis-headless --cluster-ip=None --port=6379

Step 2: Test DNS Resolution​

kubectl run dns-test -it --image=nicolaka/netshoot --rm --restart=Never -- bash

# Test 1: Same-namespace resolution
nslookup nginx-svc

# Test 2: Cross-namespace resolution (Full FQDN)
nslookup app1-svc.app1-ns.svc.cluster.local

# Test 3: External DNS
nslookup google.com # CoreDNS forwards to upstream resolver

DEMO 3: CoreDNS CONFIGURATION - COREFILE​

View CoreDNS ConfigMap:​

kubectl get configmap coredns -n kube-system -o yaml

CoreFile Breakdown:​

.:53 {
    errors          # Log errors to stdout
    health          # Health check endpoint
    ready           # Readiness endpoint
    kubernetes cluster.local in-addr.arpa ip6.arpa {
       pods insecure   # Pod DNS mode
       fallthrough in-addr.arpa ip6.arpa
       ttl 30
    }
    prometheus :9153 # Metrics endpoint
    forward . /etc/resolv.conf { # Forward external queries
       max_concurrent 1000
    }
    cache 30        # DNS cache duration
    loop            # Detect DNS loops
    reload          # Auto-reload config on change
    loadbalance     # Distribute query load
}

Pod DNS resolution modes:​

  1. pods insecure: Creates DNS records for all pod IPs without validation (not recommended for production).
  2. pods verified: (Recommended) Validates that a pod exists via API server before returning the IP.
  3. pods hostname: Uses the pod's hostname field; useful for StatefulSets.

DNS TROUBLESHOOTING CHECKLIST​

  1. Check CoreDNS Pods: kubectl get pods -n kube-system -l k8s-app=kube-dns
  2. Check CoreDNS Logs: kubectl logs -n kube-system -l k8s-app=kube-dns
  3. Test from a Pod: nslookup kubernetes.default or nslookup nginx-svc.default.svc.cluster.local
  4. Verify /etc/resolv.conf: Ensure nameserver IP matches kubectl get svc -n kube-system kube-dns.
  5. Check CoreFile: Ensure no syntax errors in the ConfigMap.
  6. Verify nsswitch.conf: Should be hosts: files dns.
  7. Check Network Policies: Ensure traffic is not blocked on Port 53 (UDP/TCP).
  8. Validate Kubelet flags: Especially --cluster-dns.
  9. Look for Loops: Ensure CoreDNS pods aren't forwarding to themselves (check /etc/resolv.conf on the node).
