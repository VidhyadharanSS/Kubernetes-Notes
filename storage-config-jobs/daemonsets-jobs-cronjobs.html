Kubernetes - Configmaps & Secrets

CONFIGMAPS​

  • Purpose: Decouples configuration data (non-confidential) from container images.
  • Usage: Stores key-value pairs or entire configuration files.
  • Size Limit: Maximum size for a ConfigMap is 1MB.
  • Consumption Methods:
    1. As environment variables: (Individual keys via valueFrom or all keys via envFrom).
    2. As command-line arguments: Used in the command or args section of a container.
    3. As configuration files via mounted volumes: Mounted as a directory or specific files.

Note on Updates:

  • Volumes: If a ConfigMap is mounted as a volume, Kubelet syncs it periodically (default ~1 min). The application must be able to "hot-reload" files to see changes without a restart.
  • Env Vars: Environment variables are static. If the ConfigMap changes, you must restart the Pod (usually via a rollout) to see the new values.

DEMO - CONFIGMAPS​

1. Loading All Keys at Once (envFrom)​

Instead of mapping every key manually, use envFrom to inject all keys as environment variables automatically.

spec:
  containers:
  - name: app-container
    image: nginx
    envFrom:
    - configMapRef:
        name: frontend-cm

2. Advanced Mounting with items:​

The items section allows you to project specific keys into specific file paths and even rename the files.

volumes:
- name: config-volume
  configMap:
    name: frontend-cm
    items:
    - key: index.html
      path: startup-page.html # The key 'index.html' is renamed to 'startup-page.html' on disk
    - key: APP
      path: app_name.txt

3. Immutable ConfigMaps (v1.19+)​

For clusters where configuration shouldn't change, you can mark a ConfigMap as immutable. This improves performance (Kubelet stops polling for changes) and prevents accidental edits.

apiVersion: v1
kind: ConfigMap
metadata:
  name: static-config
immutable: true
data:
  version: "1.0"

SECRETS​

  • Purpose: Stores sensitive information (passwords, tokens, keys).
  • Encoding: Data is Base64 encoded, not encrypted.
  • Types of Secrets:
    TypeUsage
    OpaqueDefault type for user-defined arbitrary key-value pairs.
    kubernetes.io/service-account-tokenUsed for ServiceAccount credentials.
    kubernetes.io/dockerconfigjsonUsed for imagePullSecrets to authenticate with private registries.
    kubernetes.io/basic-authFor username/password authentication.
    kubernetes.io/ssh-authFor SSH private keys.
    kubernetes.io/tlsFor storing TLS certificates and keys.

DEMO - SECRETS​

1. Data vs StringData​

  • data: Values must be manually base64 encoded.
  • stringData: Allows you to write plain-text values. Kubernetes will base64 encode them automatically when you apply the manifest. (Note: stringData is write-only; it becomes data when you get the secret later).
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
stringData:
  password: "PlaintextPassword123" # Kubernetes encodes this for you

2. Using Image Pull Secrets​

To pull an image from a private Docker Registry:

spec:
  imagePullSecrets:
  - name: my-registry-key
  containers:
  - name: private-app
    image: my-private-repo/app:v1

3. Mounting Secrets with Renaming (items:)​

volumes:
- name: cert-volume
  secret:
    secretName: frontend-secret
    items:
    - key: DB_PASSWORD
      path: db_pass.txt # Mounts the password key into a file named db_pass.txt

Summary Checklist for Prep:​

  1. Scope: Both are Namespace-scoped resources.
  2. Size: Both have a 1MB limit.
  3. Security:
    • Secrets are stored in tmpfs (RAM) on the Node, so they aren't written to the Node's physical disk.
    • Always enable Encryption at Rest in etcd for Secrets.
  4. SubPath Update Issue: If you use subPath to mount a single file from a ConfigMap/Secret, that file will not update automatically when the source changes (unlike a full directory mount).
  5. Immutability: Once set to immutable: true, you cannot change the data or stringData. You must delete and recreate the resource.
  6. Usage with envFrom: If a key in the ConfigMap/Secret is "invalid" as an env var name (e.g., starts with a digit), that specific key will be skipped, but the Pod will still start.
