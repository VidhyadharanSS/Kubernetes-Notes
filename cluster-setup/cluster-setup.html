Kubernetes Cluster Setup - kubeadm

0. Architecture & Firewall Requirements​

Control Plane Node Inbound:

  • TCP 6443: Kubernetes API Server (Accessed by workers and admin).
  • TCP 2379–2380: etcd server API (Internal Control Plane communication).
  • TCP 5473: Calico Typha (Management proxy for Calico nodes).
  • UDP 4789: Calico VXLAN (Pod-to-Pod communication).

Worker Nodes Inbound:

  • TCP 10250: Kubelet API (Used by Control Plane to manage pods).
  • UDP 4789: Calico VXLAN (Pod-to-Pod communication).
  • TCP 30000–32767: NodePort Services (External access to your applications).

Common:

  • TCP 22: SSH access for the administrator.

Step 1: System Preparation & Kernel Tuning [ALL NODES]​

We must disable features that interfere with Kubernetes and enable kernel modules required for container networking.

Explanation:

  • Swap: Kubelet’s resource tracking is not designed for swap. If swap is active, performance becomes unpredictable, and the Kubelet will fail to start.
  • Overlay & br_netfilter: overlay is required for the container storage driver. br_netfilter allows the host's bridge to pass traffic to iptables for filtering, which is essential for CNI operation.
  • IP Forwarding: Essential for the node to act as a router and forward traffic from the pod network to other nodes.
# Disable Swap
sudo swapoff -a
sudo sed -i '/ swap / s/^/#/' /etc/fstab

# Enable Kernel Modules
echo -e "overlay\nbr_netfilter" | sudo tee /etc/modules-load.d/k8s.conf
sudo modprobe overlay
sudo modprobe br_netfilter

# Configure Networking Sysctl
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system

Step 2: Container Runtime - containerd [ALL NODES]​

Kubernetes uses the Container Runtime Interface (CRI) to run containers. We are using containerd.

Explanation:

  • config.toml: This is the primary configuration file for containerd.
  • SystemdCgroup: By default, Kubernetes uses systemd as the cgroup driver. We must tell containerd to use the same driver, or the Kubelet will crash.
  • Sandbox Image: The "Pause" container is a tiny image that holds the network namespace open for every Pod. We pin it to version 3.9 to ensure compatibility with K8s 1.32.
# Install containerd
sudo apt-get update && sudo apt-get install -y containerd

# Generate and modify configuration
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null

# Set Cgroup driver to systemd
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

# Set the correct sandbox image version
sudo sed -i 's#sandbox_image = ".*"#sandbox_image = "registry.k8s.io/pause:3.9"#' /etc/containerd/config.toml

# Restart to apply changes
sudo systemctl restart containerd

Step 3: Install Kubernetes Tools [ALL NODES]​

We install the three core binaries: kubeadm (cluster bootstrapper), kubelet (node agent), and kubectl (command-line tool).

Explanation:

  • Apt Repository: We use the official pkgs.k8s.io community repository for v1.32.
  • Apt-mark hold: This prevents the packages from being updated automatically. In production, you only upgrade K8s via a controlled, manual process.
# Install prerequisites
sudo apt-get install -y apt-transport-https ca-certificates curl gpg
sudo mkdir -p /etc/apt/keyrings

# Add Kubernetes GPG key and Repository
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.32/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.32/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

# Install binaries
sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

Step 4: Initialize the Control Plane [CONTROL PLANE ONLY]​

This command bootstraps the cluster's internal components (API Server, Scheduler, Controller Manager, and etcd).

Explanation:

  • --pod-network-cidr: This defines the internal IP range for Pods. Calico’s default is 192.168.0.0/16.
  • --apiserver-advertise-address: The Private IP of the Control Plane node that workers will use to connect.
  • admin.conf: This file contains the root credentials for your cluster.
# Bootstrap the cluster
sudo kubeadm init \
  --pod-network-cidr=192.168.0.0/16 \
  --apiserver-advertise-address=<CONTROL_PLANE_PRIVATE_IP>

# Set up local kubeconfig for the user
mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

Step 5: Install Calico CNI (Operator Method) [CONTROL PLANE ONLY]​

The Tigera Operator manages the installation and lifecycle of Calico.

Explanation:

  • VXLANCrossSubnet: This tells Calico to use VXLAN (UDP 4789) for traffic that needs to cross subnet boundaries.
  • BGP Disabled: Cloud providers (AWS/Azure) often block BGP. Disabling it avoids "BIRD" errors and forces the cluster to use VXLAN for the overlay.
# Install Tigera Operator and CRDs
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.30.2/manifests/operator-crds.yaml
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.30.2/manifests/tigera-operator.yaml

# Apply the network configuration
cat <<EOF | kubectl apply -f -
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    bgp: Disabled
    ipPools:
    - cidr: 192.168.0.0/16
      encapsulation: VXLANCrossSubnet
EOF

Step 6: Join Worker Nodes [WORKERS ONLY]​

To join the data plane nodes to the control plane, generate a join command.

# Run this on the Control Plane to get the command
kubeadm token create --print-join-command

# Run the output of the above command on each Worker Node with 'sudo'
# Example: sudo kubeadm join <IP>:6443 --token <token> --discovery-token-ca-cert-hash <hash>

7. Verification & Troubleshooting​

Verify Nodes and Pods:

kubectl get nodes
kubectl get pods -A

Common Issues:

  • Nodes stay "NotReady": Check if Calico pods are running. Usually caused by blocked TCP 5473 (Typha) or UDP 4789 (VXLAN) in your firewall.
  • BIRD Errors in Logs: This happens if BGP is enabled but blocked. Ensure bgp: Disabled was set in the Calico Installation spec.
  • Cgroup Driver Mismatch: If the Kubelet fails to start, check journalctl -u kubelet. If it says "failed to create container: cgroup driver mismatch", revisit Step 2 to ensure SystemdCgroup is set to true in config.toml.

Summary of Critical Files​

  1. /etc/containerd/config.toml: Runtime settings (SystemdCgroup and Pause image).
  2. /etc/sysctl.d/k8s.conf: Kernel settings for networking/routing.
  3. /etc/kubernetes/admin.conf: The "Master Key" credentials for cluster administration.
  4. $HOME/.kube/config: The local copy of credentials used by kubectl.
