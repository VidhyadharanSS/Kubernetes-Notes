Linux Fundamentals & System Architecture

1. The Core of Linux​

Linux is an open-source OS Kernel. It is not a full Operating System by itself; it is the "engine" that manages communication between software and hardware.

Historical Context​

  • 1969 (UNIX): Created at Bell Labs. It was proprietary and expensive.
  • 1983 (GNU Project): Richard Stallman founded the Free Software Foundation. He aimed to build a free UNIX-like OS. He created the "Userland" tools (Compiler, Shell, Editor).
  • 1987 (Minix): A small UNIX-like system created for education.
  • 1991 (Linux): Linus Torvalds created the Linux Kernel as a personal project because he wanted a free version of Minix.
  • GNU/Linux: What we call "Linux" today is actually the GNU tools running on top of the Linux Kernel.

The 3-Layer Component Model​

LayerRoleDescription
KernelResource ManagerManages CPU, RAM, Disk, and Hardware Drivers.
ShellCommand InterpreterA program (like Bash or Zsh) that takes user input and passes it to the Kernel.
UserlandApplication SpaceWhere user applications (Browsers, Web Servers, Editors) run.

2. The Linux Boot Sequence​

Understanding this is critical for troubleshooting system-level failures.

  1. BIOS/UEFI: The first code to run. It performs POST (Power On Self Test) to verify hardware like RAM and Keyboard.
  2. MBR/GPT (Bootloader Search): The system looks for the bootable device (Disk).
  3. Bootloader (GRUB2): A small program on the disk that allows you to select the OS. It loads the Kernel into memory (RAM).
  4. Kernel Initialization: The kernel starts hardware drivers and mounts the root filesystem (/).
  5. Init Process (PID 1): The kernel starts the very first process in userspace.

3. Process Management: PID 1​

The Init Process always has Process ID 1. It is the parent of all other processes.

  • Spawning: Every application you run is a "Child" of the process that started it.
  • Adopting Orphans: If a parent process dies unexpectedly, PID 1 "adopts" the children to ensure they are monitored and eventually cleaned up.
  • Zombie Processes:
    • What it is: A process that has finished execution but still has an entry in the Process Table.
    • The Cause: The parent process failed to call the wait() system call to collect the exit status.
    • The Danger: Zombies don't use RAM, but they consume PIDs. If you reach the system's PID limit, you cannot start any new processes (including ls or ssh).
    • The Fix: You cannot "kill" a zombie because it is already dead. You must kill/restart the Parent process.

4. Startup Systems: SysV Init vs. Systemd​

SysV Init (The Legacy Way)​

  • Logic: Uses Runlevels (0: Halt, 1: Single User, 3: Multi-user CLI, 5: GUI, 6: Reboot).
  • Execution: Sequential. It starts Service A, waits for it to finish, then starts Service B. This makes booting very slow.

Systemd (The Modern Standard)​

  • Logic: Uses Target Units (e.g., multi-user.target).
  • Execution: Parallel. It starts multiple services at once, resulting in significantly faster boot times.
  • Naming: Background processes are called Daemons (ending in "d", e.g., systemd, sshd, dockerd).
RunlevelSystemd TargetDescription
0poweroff.targetShuts down the system.
1rescue.targetSingle-user mode (Maintenance).
3multi-user.targetMulti-user mode, CLI only (Standard for Servers).
5graphical.targetMulti-user mode with GUI.
6reboot.targetReboots the system.

Mastering systemctl​

CommandPurpose
systemctl start <svc>Start a service (current session only).
systemctl stop <svc>Stop a service.
systemctl restart <svc>Stop and then start.
systemctl enable <svc>Configure service to start automatically on boot (creates a symlink).
systemctl disable <svc>Stop service from starting on boot.
systemctl status <svc>View active state, Main PID, and recent logs.
systemctl is-enabled <svc>Check if it will start on next boot.

5. Package Management (Debian/Ubuntu)​

The APT (Advanced Package Tool) manages software.

  1. sudo apt update: Refreshes the local repository index (the list of what is available).
  2. sudo apt install <name> -y: Downloads and installs.
  3. sudo apt remove <name>: Deletes the package but keeps config files.
  4. sudo apt purge <name>: Deletes the package AND config files.
