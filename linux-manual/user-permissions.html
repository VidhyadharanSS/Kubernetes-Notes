User, Group & Permission Manual

1. User Identity Management​

Linux is a multi-user system where every process and file is owned by a specific identity. Identity is defined by UID (User ID) and GID (Group ID).

A. The /etc/passwd File (Account Information)​

This file is world-readable and contains the basic attributes of every user on the system.

Format: username:password_placeholder:UID:GID:GECOS:home_directory:shell

FieldDescription
UsernameUnique login name (e.g., root, vboxuser).
PasswordUsually an x, indicating the actual hashed password is in /etc/shadow.
UID0: Root. 1-999: System users (daemons/services). 1000+: Human users.
GIDThe primary group ID for this user.
GECOSGeneral info/Comments (often the user's full name).
Home DirPath to user's home (e.g., /home/alice).
ShellDefault CLI (e.g., /bin/bash). Service accounts often use /usr/sbin/nologin.

B. The /etc/shadow File (Secure Credentials)​

Only readable by root. It stores hashed passwords and aging metadata.

Format: username:hash:lastchange:min:max:warn:inactive:expire:reserved

FieldMeaning
UsernameMust match the entry in /etc/passwd.
Hashed PasswordStarts with $id$. $1$=MD5, $5$=SHA-256, $6$=SHA-512 (Modern default).
Last ChangeDays since Jan 1, 1970 (Unix Epoch) that the password was last changed.
Min DaysMinimum days required before the user is allowed to change password again.
Max DaysNumber of days before the password must be changed.
Warn DaysDays before expiration to start showing a warning message at login.
InactiveDays after password expires before the account is totally disabled.
ExpireAbsolute date (days since epoch) when the account will be disabled.

C. Essential Identity Commands​

  • id <user>: Displays UID, Primary GID, and all secondary groups.
  • whoami: Returns the effective username of the current session.
  • useradd -m <user>: Creates a new user and generates a home directory.
  • usermod -aG <group> <user>: Adds a user to a supplementary group.
    • Warning: Always use -a (append). Without it, the user is removed from all other groups.
  • userdel -r <user>: Deletes user and removes their home directory.

2. Group Management​

Groups allow you to apply the same permissions to multiple users at once.

  • Source File: /etc/group $\rightarrow$ groupname:password:GID:user_list

Essential Commands​

  • groupadd <name>: Create a new group.
  • groupadd -g 2000 <name>: Create a group with a specific GID.
  • groups <user>: List all groups a specific user belongs to.
  • groupdel <name>: Delete a group.

3. Linux File Permissions​

Run ls -l to view permissions. The first 10 characters define the access level.

Breakdown: - rwx r-x r--​

  1. Position 1: Type (-=File, d=Directory, l=Link).
  2. Positions 2-4 (Owner): Permissions for the user who owns the file.
  3. Positions 5-7 (Group): Permissions for users in the file's group.
  4. Positions 8-10 (Others): Permissions for everyone else on the system.

Numeric (Octal) vs Symbolic​

ValueSymbolicMeaning
4r--Read: View contents (File) or List files (Dir).
2-w-Write: Modify contents (File) or Create/Delete files (Dir).
1--xExecute: Run as program (File) or Enter/CD into (Dir).

Common Masks:

  • 755 (rwxr-xr-x): Standard for scripts/directories.
  • 644 (rw-r--r--): Standard for configuration files.
  • 600 (rw-------): Private files (like SSH keys).

4. Special Permissions (Hardening)​

Used when standard rwx is insufficient for system operations.

  1. SUID (Set User ID) - u+s:
    • Effect: The file runs with the privileges of the File Owner, not the user running it.
    • Visual: rwsr-xr-x. If the 's' is capital (S), the execute bit is missing.
    • Example: /usr/bin/passwd (allows users to write to /etc/shadow).
  2. SGID (Set Group ID) - g+s:
    • On Files: Runs with group privileges.
    • On Directories: Any new files created inside inherit the parent directory’s group.
    • Use Case: Collaborative folders where everyone needs to work on the same group files.
  3. Sticky Bit - +t:
    • Effect: Only the Owner of a file (or Root) can delete or rename it, even if others have write access to the directory.
    • Visual: rwxrwxrwt.
    • Example: /tmp directory.

5. Ownership Management​

  • chown <user> <file>: Change the individual owner.
  • chown <user>:<group> <file>: Change both owner and group at once.
  • chgrp <group> <file>: Change the group ownership only.
  • -R flag: Use with chown/chmod to apply changes recursively to all files inside a directory.

6. Sudo and Privilege Escalation​

The sudo (SuperUser Do) command allows a user to run programs with the security privileges of another user (usually root).

The /etc/sudoers File​

  • sudo visudo: Always use this command to edit sudoers. It locks the file and performs a syntax check. A single typo in this file can break your system's root access.
  • Syntax: user host=(runas_user:runas_group) commands
    • %admin ALL=(ALL) ALL $\rightarrow$ Members of group admin have full sudo.
    • alice ALL=(ALL) NOPASSWD: /usr/bin/apt $\rightarrow$ Alice can run apt without a password.

Key Privilege Commands​

  • sudo -i: Opens a persistent root login shell.
  • sudo !!: Re-runs the last command entered with sudo (very common in workflows).

Summary: Permission Impact​

PermissionOn a FileOn a Directory
Read (r)Read file content (cat, vi).List files inside (ls).
Write (w)Edit/Change file contents.Add, delete, or rename files inside.
Execute (x)Run the file as a script/binary.cd into the directory or access sub-files.
