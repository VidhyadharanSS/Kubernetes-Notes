Kustomize - Basics and Demos

Kustomize is a native Kubernetes configuration management tool for environment-specific customization without templating. It uses a declarative base + overlays approach.

The Problem​

  • Multiple Environments: (dev, staging, prod) need slightly different configs.
  • Manual Duplication: Copy-pasting YAML causes errors and "config drift."
  • Complexity: A single application across 3 tiers and 3 environments can result in ~45 objects to manage manually.

Core Concepts​

  • Base: Common configuration shared across all environments (standard YAML).
  • Overlays: Environment-specific customizations that "patch" the base.
  • No Templating: Pure YAML with declarative patches (unlike Helm’s Go templates).
  • Native: Bundled with kubectl (v1.14+).

Kustomize vs Helm​

FeatureKustomizeHelm
Native to K8sYes (built into kubectl)No (separate binary)
TemplatingNoYes (Go templates)
VariablesNoYes (values.yaml)
ComplexityLowMedium-High
Package ManagementNoYes (Charts)
Logic/LoopsNoYes
Use CaseSimple to medium appsMedium to complex apps

Installation​

  • Bundled: Part of kubectl since v1.14. Use kubectl apply -k.
  • Standalone: 
    curl -s "https://raw.githubusercontent.com/kubernetes-sigs/kustomize/master/hack/install_kustomize.sh" | bash

Deep Dive: Kustomization.yaml​

Critical Rule: The file must be named exactly kustomization.yaml (all lowercase). Kustomization.yaml or kustomization.yml will not work.

Recommended Directory Structure​

kustomize-demo/
├── base/
│   ├── deployment.yaml
│   ├── service.yaml
│   └── kustomization.yaml
└── overlays/
    ├── dev/
    │   └── kustomization.yaml
    ├── staging/
    │   └── kustomization.yaml
    └── prod/
        └── kustomization.yaml

In base/​

Lists raw Kubernetes YAML files with no environment-specific customizations.

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deploy.yaml
  - svc.yaml

In overlays/​

References the base via a relative path and applies customizations.

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base
nameSuffix: -dev

Transformers​

Built-in mechanisms to modify resources declaratively without editing raw YAML.

Common Transformers​

  • namePrefix / nameSuffix: Add prefixes/suffixes to all resource names.
  • namespace: Assign a specific namespace to all resources.
  • images: Override container image names or tags.
  • replicas: Change replica count for specific deployments.
  • labels: Add labels to metadata and selectors. includeSelectors: true ensures consistency.
  • commonAnnotations: Add annotations to all resources.

Limitations​

Transformers cannot modify:

  • Arbitrary nested fields in container specs.
  • Specific containerPort values.
  • Environment variables (limited support).
  • Volume mounts or probes.
  • Deeply nested fields beyond exposed transformers.

Patches (The Preferred Solution)​

Precise, field-level modifications for deeply nested fields not supported by transformers.

JSON Patch Operations (RFC 6902)​

  • add: Add new field/array entry.
  • replace: Replace value (field must exist).
  • remove: Delete field/element.
  • copy: Copy value between paths.
  • move: Move value between paths.

Patch Methods​

MethodFormatStatus
patches (generic)YAML/JSON inlinePreferred
patchesJson6902JSON patch fileDeprecated
patchesStrategicMergeYAML fileDeprecated

DEMO 1: Name Suffix Transformer​

Base Files: deploy.yaml (name: nginx-deploy), svc.yaml (name: nginx-svc).

Base kustomization.yaml:

apiVersion: kustomize.config.k8s.io/v1
kind: Kustomization
resources:
  - deploy.yaml
  - svc.yaml

Dev Overlay kustomization.yaml:

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base
nameSuffix: -dev

Note: ../../base means go up two levels, then into base/.

DEMO 2: Additional Transformers​

Dev Overlay kustomization.yaml:

apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base

namePrefix: app1-
nameSuffix: -dev
namespace: dev

labels:
  - pairs:
      env: dev
    includeSelectors: true

commonAnnotations:
  branch: dev
  support: 800-800-700

images:
  - name: nginx
    newName: nginx
    newTag: "latest"

replicas:
  - name: nginx-deploy
    count: 2

DEMO 3: Patches (Modern Method)​

Inline patching in kustomization.yaml is the most flexible approach (best for Kustomize v5+).

patches:
  - target:
      group: apps
      version: v1
      kind: Deployment
      name: nginx-deploy
    patch: |-
      - op: add
        path: /spec/template/spec/containers/0/env
        value:
          - name: LOG_LEVEL
            value: debug
      - op: replace
        path: /spec/template/spec/containers/0/resources
        value:
          requests:
            cpu: "100m"
            memory: "128Mi"
          limits:
            cpu: "500m"
            memory: "256Mi"
      - op: remove
        path: /metadata/labels/unused

  - target:
      version: v1
      kind: Service
      name: nginx-svc
    patch: |-
      - op: replace
        path: /spec/ports/0/nodePort
        value: 31000

Operations Explained:​

  • add: Injects LOG_LEVEL=debug to the container.
  • replace: Overwrites the resources block and hardcodes a nodePort.
  • remove: Deletes an unused metadata label.

Kustomize Commands​

Critical: Commands must run in a directory containing a kustomization.yaml or reference that directory.

View Generated Manifests​

kubectl kustomize base
kubectl kustomize overlays/dev
kubectl kustomize overlays/stage

Apply Configuration​

# Create namespaces first
kubectl create namespace dev
kubectl create namespace stage
kubectl create namespace prod

# Apply using -k (Kustomize directory)
kubectl apply -k overlays/dev
kubectl apply -k overlays/stage
kubectl apply -k overlays/prod

Note: -k is for Kustomize directories; -f is for standard files.

Deprecated Methods and Migration​

  • Deprecated: patchesJson6902 and patchesStrategicMerge.
  • Why: Brittle with custom resources, lacks flexibility compared to the unified patches field.
  • Migration: From the overlay directory, run: 
    kustomize edit fix
    This auto-converts deprecated sections to the modern patches format.

Common Pitfalls​

  1. Replace vs Add: Using replace for a field that doesn't exist yet (must use add).
  2. Path Syntax: Using incorrect path syntax for nested fields (use / for nesting).
  3. Missing File: Forgetting to include a kustomization.yaml in a directory.
  4. CLI Flags: Using -f instead of -k during kubectl apply.
  5. Relative Paths: Providing incorrect relative paths to the base in overlays.
  6. Naming: Naming the file Kustomization.yaml or kustomization.yml (Must be lowercase .yaml).
